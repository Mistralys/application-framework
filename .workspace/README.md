# .workspace

This folder holds repository information for multi-repository workspaces, managed by the Paralizer tool.

`info.json` is generated: its `Name`, `Description`, `Url` and `Files` fields are written by Paralizer from the data it holds. Manual edits are overwritten on the next sync unless made through Paralizer.

Credentials and other machine-local settings are never stored here.

Changes made in this folder are reviewed and committed by the repository owners, like any other change.

To find Paralizer: see the `AGENTS.md` file at the root of the surrounding workspace folder — it carries a "Paralizer CLI" section describing where it is installed and how to use it.

## files/

The sibling `files/` folder holds small per-repository files — such as wrapper scripts — that Paralizer syncs through git, alongside this repository, for every teammate working on it.

These files are delivered through git only: Paralizer never pushes or pulls them over any other channel. Commit and push them like any other change, and pull to pick up a teammate's addition.

Every file under `files/` is maintained by Paralizer: a manual edit made directly in this folder is overwritten on the next sync unless made through Paralizer.

A script under `files/` marked executable can be run directly, e.g. `sh .workspace/files/<name>.sh`, from the repository root.

Each file's label, description and flags are listed in `info.json`'s `Files` array.
